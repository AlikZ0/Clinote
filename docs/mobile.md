# Mobile

Mobile is the primary target: the product is used standing next to a patient,
one-handed, on a phone.

## 1. Language

The interface ships in English, Russian and Armenian. The locale is detected
from the browser on first run and can be changed in Settings; the choice is
stored in the local settings table, like everything else (docs/local-first.md
§9).

English is the source catalogue: the others are typed against it, and a test
checks that every key exists in every language and that no translation drops a
placeholder such as `{count}`. A missing message falls back to English and then
to the key, so a gap can never render as an empty element.

Armenian is why the font stack names `Noto Sans Armenian` before the generic
fallbacks.

## 2. Layout (§55)

|            | Desktop             | Mobile                                                |
| ---------- | ------------------- | ----------------------------------------------------- |
| Navigation | left sidebar        | bottom bar: Home · Clients · Calendar · Backup · More |
| Lists      | table + detail pane | full-width virtualized list → detail push             |
| Forms      | modal               | full-screen sheet                                     |
| Actions    | toolbar             | thumb-reachable primary action                        |

Locked Pro items stay visible in navigation as upgrade opportunities rather than
disappearing, so the product's value is discoverable (§55, §56).

Touch targets ≥ 44 px, safe-area insets respected, no hover-only affordances,
`inputmode`/`autocomplete` set on every field.

## 3. iOS Safari — the hard constraints

| Constraint                                                          | Impact                           | Mitigation                                                                                                                         |
| ------------------------------------------------------------------- | -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Storage evicted after ~7 days of inactivity for non-installed sites | **loss of the system of record** | request persistent storage; prompt Add to Home Screen before real data is entered; export reminders; explicit onboarding copy (R1) |
| Web Push only in an installed PWA, iOS 16.4+                        | reminders silently absent        | capability detection, email fallback, honest UI ("Enable on this device: add Clinote to your Home Screen")                         |
| No `showSaveFilePicker`                                             | export downloads                 | share sheet / download fallback, tested on-device                                                                                  |
| Aggressive tab suspension                                           | interrupted long operations      | resumable, chunked backup/restore/import                                                                                           |
| Memory pressure on large blobs                                      | tab crash                        | stream and chunk; never hold a full archive in memory                                                                              |
| Camera capture orientation/EXIF                                     | rotated x-rays                   | normalize orientation on ingest                                                                                                    |

## 4. Android Chrome

Fewer constraints: installable PWA, Web Push, file picker, camera. Still test
storage pressure and background-tab throttling of the sync drain.

## 5. Capture flow

`<input type="file" accept="image/*,application/pdf" capture>` for photos and
x-rays, multi-select for batch import, client-side downscale for the thumbnail,
original preserved untouched (an x-ray must never be recompressed).

## 6. What Phase 4 shipped

| Piece                                                        | Where                                                                                    |
| ------------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| Manifest, icons (incl. maskable), iOS meta tags              | `nuxt.config.ts` `app.head` + `pwa.manifest`, `public/icons/`                            |
| Service worker (precache app shell, SPA navigation fallback) | generated by `@vite-pwa/nuxt`, Workbox `generateSW`                                      |
| Registration and the update handshake                        | `composables/useServiceWorker.ts`, `plugins/pwa.client.ts`                               |
| Update offered, never forced                                 | `components/PwaUpdatePrompt.vue`                                                         |
| Storage risk assessment and the action that fixes it         | `utils/platform.ts`, `composables/useStorageGuard.ts`, `components/StorageGuardCard.vue` |
| Install prompt (Chromium) / manual instructions (Safari)     | `composables/useInstallPrompt.ts`                                                        |
| "Your data stays on this device" onboarding                  | `components/FirstRunNotice.vue`                                                          |
| Persistence requested right after the first real write       | `useStorageGuard().ensureRequestedAfterFirstWrite()`                                     |

Two deliberate choices:

- **Clinote registers the service worker itself.** The offline guarantee is the
  product, so registration is ~40 lines we can read and reason about rather than
  a module side effect. `@vite-pwa/nuxt` is kept for generating `sw.js` and the
  manifest, with `injectRegister: false` and `client.registerPlugin: false` so
  there is exactly one owner.
- **The manifest link and the Apple meta tags are declared explicitly** in
  `app.head`. They were missing from the generated HTML when left to the module,
  and a missing manifest means no browser ever offers to install the app —
  which would silently disable the entire R1 mitigation.

- **No runtime caching of API responses.** A stale entitlement or stale backup
  metadata is worse than an honest offline state (docs/local-first.md §8).

## 7. Offline UX (§69)

A single status chip: 🟢 Online / 🟠 Offline (+ Sync state for Pro). Offline
never disables a local action, and there is no blocking full-screen offline
state.

## 8. Manual test matrix (§80)

iPhone Safari · iPhone installed PWA · Android Chrome · Android installed PWA ·
desktop Chrome · desktop Safari · Firefox.

Per target: install, create client, attach photo, attach PDF, reload, kill and
reopen the app, export, import, offline mutation, reconnect, (Pro) push
permission, reminder delivery, backup, restore.

**Service worker behaviour is manual-only.** The rules that decide _what_ the
user is told (`utils/platform.ts`) are unit-tested, but activation, precache and
offline navigation depend on a real browser. Per release, on at least one
Chromium and one Safari target:

1. Load the app, wait for the worker to activate (`navigator.serviceWorker.controller` is set after one reload).
2. Disconnect the network, reload: the app shell must render and the local data must be there.
3. Open a deep link (`/clients/<id>`) offline: the navigation fallback must serve it.
4. Deploy a new build, reload: the update bar appears and applies only on click.
5. iOS: add to Home Screen, confirm standalone display and that the storage card stops reporting critical risk.
6. Turn on push in Settings, book an appointment with a 30-minute reminder, and
   confirm the notification arrives and names the client — proving the payload
   was rendered on the device, since the payload itself carries only a
   reference (docs/notifications.md §2).

## 9. Automated coverage

Playwright projects for mobile viewport emulation cover layout and flows;
storage eviction, real push and camera are manual-only and tracked in a
per-release checklist under `docs/`.
